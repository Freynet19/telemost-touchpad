# Telemost Touchpad

Заставляет кнопки **Dell Collaboration Touchpad** (микрофон, камера, демонстрация экрана, чат) работать с десктопным
**Яндекс Телемостом**, который Dell Optimizer не поддерживает. Проверено на Dell Latitude 9440.

[English version](README.md) (основная)

> **Статус:** работает у автора на одной машине. Проект неофициальный и опирается на недокументированное поведение
> Dell Optimizer и Телемоста: любое их обновление может его сломать. Не связан с Dell, Яндексом и Microsoft.

## Как это работает

Dell Optimizer зажигает и читает кнопки тачпада, когда идёт встреча в Zoom, Teams или Webex. С Teams он общается по
локальному WebSocket API. Проект изображает для Optimizer Teams и связывает это с Телемостом:

```
кнопка тачпада --> Dell Optimizer --(Teams API, ws://127.0.0.1:8124)--> fake-teams --> telemost-bridge --UI Automation--> Телемост
подсветка       <-- Dell Optimizer <-------- состояние встречи -------- fake-teams <-- telemost-bridge <-- Телемост
```

- `fake-teams` — сервер на loopback, который говорит с Optimizer на языке «Teams third-party device API».
- `telemost-bridge` — читает окно звонка Телемоста через UI Automation и применяет к нему команды с тачпада.

| Кнопка тачпада | Обычное окно звонка | Во время показа экрана (мини-окно) |
|---|---|---|
| Микрофон | реально включает и выключает | работает (кнопка микрофона мини-окна) |
| Камера | реально запускает и останавливает | работает (через меню «…», оно на миг мелькает) |
| Шаринг | открывает диалог выбора Телемоста, повторное нажатие закрывает | останавливает показ |
| Чат | открывает и закрывает панель чата | недоступно |

Подсветка следует за реальным состоянием Телемоста, в том числе когда ты меняешь его мышью. Кнопка чата «дышит»,
когда приходят новые сообщения при закрытом чате. Кнопки горят только пока есть окно звонка; если открыто лишь
главное окно Телемоста, они не горят. (Экран перед входом в звонок не проверялся.)

## Требования

- Ноутбук Dell с Collaboration Touchpad и **Dell Optimizer** (проверено: Latitude 9440, Optimizer 4.2.4.0).
- **Телемост** (проверено: 3.2.2.10363), Windows 11 (проверено: 10.0.26300).
- Среды .NET 10 x64 (*.NET Desktop Runtime* и *ASP.NET Core Runtime*); для сборки .NET 10 SDK. Права администратора
  не нужны.

Настоящий Microsoft Teams одновременно запускать нельзя: он занял бы порт 8124.

## Установка

```powershell
git clone <этот репозиторий>
cd telemost-touchpad
.\build.ps1                                                           # собирает обе программы в .\dist
powershell -ExecutionPolicy Bypass -File .\dist\install.ps1 -WhatIf   # предпросмотр, ничего не меняет
powershell -ExecutionPolicy Bypass -File .\dist\install.ps1
```

`install.ps1` (для текущего пользователя): копирует программы в `%LOCALAPPDATA%\TelemostTouchpad` (логи в `logs\`),
создаёт ключ `HKCU\SOFTWARE\Microsoft\Windows\CurrentVersion\Uninstall\Teams` (`DisplayName=Teams`), если его нет
(Optimizer продолжает искать Teams, только пока считает его установленным; содержимое ключа неважно), добавляет
автозапуск `HKCU\Software\Microsoft\Windows\CurrentVersion\Run\TelemostTouchpad` и сразу запускает. Optimizer
подключается примерно за 30 секунд и сам сопрягается на первой встрече. Файлы Dell и Телемоста не меняются.

Удаление: `.\dist\uninstall.ps1` (сначала с `-WhatIf`). Ключ `Uninstall\Teams` удаляется, только если он создан
установщиком. Запись Optimizer `HKLM\SOFTWARE\Dell\DellOptimizer\PData` требует прав администратора, удалять её
необязательно.

## Если перестало работать

1. Запущено ли: `Get-Process fake-teams, telemost-bridge`. Если нет, запусти `%LOCALAPPDATA%\TelemostTouchpad\start.ps1`
   и посмотри `logs\*.err.log` (порт 8124 занят: настоящий Teams или вторая копия).
2. Подключается ли Optimizer: в `logs\fake-teams.log` должна появиться строка `[++] ... app='Dell Optimizer'` в
   течение ~30 с. Если нет после обновления Dell: проверь ключ `Uninstall\Teams` и версию
   `Dell.Optimizer.Plugin.VoipApps.dll` (см. `docs/research-notes.md`).
3. Подключился, но кнопки не реагируют: ищи `touchpad '...' -> forwarded` в `fake-teams.log` и `COMMAND ...` в
   `telemost-bridge.log`.
4. `no call window` во время звонка: Телемост поменял интерфейс. Запусти `telemost-probe\probe-uia.ps1` (только чтение)
   и сравни имена с константами в начале `telemost-bridge\Program.cs`.

## Безопасность

Мост нажимает в Телемосте только настоящими кликами на микрофон, камеру, чат, шаринг, «Cancel» диалога, остановку
показа в мини-окне и (для камеры при показе) меню «…» с пунктом «Video». «Завершить звонок», настройки, участников,
запись и кнопку старта в диалоге выбора он не трогает и ничего не выбирает за тебя. Всё слушает только `127.0.0.1`,
но **без аутентификации**: любой локальный процесс может выдать себя за Optimizer или мост. Для одного пользователя
это допустимо, для общего компьютера нет.

## Ограничения

Чат не работает во время показа; экран или окно для показа выбираешь сам; при показе камера открывает меню «…» на
миг; команды, нажатые пока мост не запущен, теряются (старше 3 с отбрасываются); проект зависит от внутренних имён
элементов Телемоста и от того, что Optimizer принимает сервер за Teams. Подробности устройства в
[docs/research-notes.md](docs/research-notes.md) (на английском).

## Обратная связь и релизы

Сообщай о проблемах через issue по шаблону (версии Dell Optimizer, Телемоста и Windows и строки логов очень важны:
проект зависит от всех троих). Pull request'ы приветствуются; у сервера есть самотест (`fake-teams\selftest.ps1`), а
GitHub Actions при каждом push собирает обе программы и гоняет его. Модель безопасности описана в
[SECURITY.md](SECURITY.md), история изменений в [CHANGELOG.md](CHANGELOG.md). Push тега версии (например
`v0.1.0`) собирает установочный zip и прикладывает его к релизу на GitHub.

Проект неофициальный, ни Dell, ни Яндекс, ни Microsoft его не поддерживают; в репозитории нет их кода и файлов.
